```python
import numpy as np, pandas as pd

def generar_transacciones(semilla=2024):
    rng = np.random.default_rng(semilla)
    n = 60_000
    dia = np.sort(rng.integers(0, 365, n))
    fecha = pd.Timestamp("2025-01-01") + pd.to_timedelta(dia, unit="D")
    df = pd.DataFrame({
        "fecha": fecha,
        "monto": np.round(rng.lognormal(6.0, 1.0, n), 2),
        "hora": rng.integers(0, 24, n),
        "internacional": (rng.random(n) < 0.08).astype(int),
        "dispositivo_nuevo": (rng.random(n) < 0.10).astype(int),
        "compras_ultimas_24h": rng.poisson(1.2, n),
        "antiguedad_cuenta_dias": rng.integers(1, 2_000, n),
        "distancia_km": np.round(rng.exponential(15, n), 1),
    })
    t = dia / 364
    riesgo = (-8.6
              + (4.5 - 4.0 * t) * df.internacional
              + (0.3 + 4.2 * t) * df.dispositivo_nuevo
              + 2.0 * (df.hora < 6)
              + 0.6 * df.compras_ultimas_24h
              + 0.9 * np.log(df.monto / 400)
              + 1.8 * (df.antiguedad_cuenta_dias < 60)
              + 0.02 * df.distancia_km)
    df["fraude"] = (rng.random(n) < 1 / (1 + np.exp(-riesgo))).astype(int)
    df.insert(len(df.columns) - 1, "contracargo",
              np.where(df.fraude == 1, rng.random(n) < 0.92, rng.random(n) < 0.003).astype(int))
    df.insert(1, "mes", df.fecha.dt.month)
    return df

df = generar_transacciones()
```

| `hora` | Hora del día (0–23) |
| `internacional` | 1 si el comercio está en otro país |
| `dispositivo_nuevo` | 1 si la compra se hizo desde un celular o computadora que el cliente nunca había usado |

| `fraude` | 🎯 **Objetivo:** 1 si la transacción resultó ser fraude |

   - Compras legítimas bloqueadas: ___ de cada 100.
   - Comparación con la regla actual del experto: ...

<details><summary>👀 Ver un ejemplo de informe</summary>

**1. Veredicto.** El 99.6 % reportado no es confiable: el modelo hacía trampa sin querer y se evaluó de una forma que esconde sus debilidades. Aun así, una versión corregida sí ahorra dinero: recomendamos usarla con una regla que tenga en cuenta el monto de cada compra.

**2. Qué encontramos.**
- *Exactitud:* como solo el 1 % de las compras es fraude, "no bloquear nunca nada" ya acierta el 99 %. El 99.6 % solo mejora eso en medio punto y no dice cuánto dinero se salva.
- *Contracargo:* el modelo se apoyaba sobre todo en saber si el cliente **reclamó** el cargo, algo que ocurre semanas después de la compra. En el momento de decidir esa información no existe. Sin ella, el modelo original era peor que no hacer nada.
- *Validación:* se mezclaron meses al evaluar, así que el modelo "conocía el futuro". Los defraudadores cambian de táctica durante el año; evaluando como en la vida real (entrenar con el pasado, probar con el futuro), el desempeño es un 15–25 % menor de lo que sugería su método.

**3. Cuánto vale.** En los últimos tres meses del año (que el modelo nunca vio), el fraude habría costado ~$82,000 al mes sin modelo y ~$33,000 con nuestra propuesta: **un 60 % menos**. A cambio, se bloquean unas 6 de cada 100 compras, la gran mayoría legítimas, que cuestan una llamada de verificación. La regla del experto ("bloquear todo lo que pase de $3,000") ahorra menos de la mitad que eso; la propuesta original del equipo (umbral 0.5) casi no ahorraba nada.

**4. Cómo usarlo.** Para cada compra, el modelo estima la probabilidad de fraude. Si esa probabilidad multiplicada por el monto supera los $25 que cuesta una verificación, se bloquea. Así somos más estrictos con las compras grandes y más tolerantes con las pequeñas.

**5. Riesgos.** Los defraudadores se adaptan: el modelo perdió calidad en solo tres meses. Hay que medir cada mes el costo real del fraude y reentrenar con los datos más recientes. El costo de $25 por bloqueo es una estimación: si la molestia al cliente cuesta más (clientes que se van), hay que recalcular la regla. Antes de usarlo con todos, conviene probarlo con una parte de las transacciones.
